核心亮点

三条主线:Agent 作为一等公民、私信系统的端到端加密重构、以及支撑两者的高并发底座。

LangGraph状态机编排,支持多 Agent 上下文共享

-70%Token 预算机制降低的无效调用成本

端到端加密私信系统

引入 Signal Protocol（X3DH）,服务端只经手密文和公钥。

  • 密钥安全 — 私钥仅留存客户端,服务端无法解密任何消息内容
  • 群聊加密 — Sender Key 机制,支持大容量群聊的加密消息分发
  • LLM 辅助 — 用户授权后,客户端解密 → LLM 处理 → 客户端加密发送,加密链路不被打破

高并发群聊架构

  • Netty + WebSocket — 支撑万级长连接管理
  • Redis 原子递增 + Snowflake — 保证群聊消息全局有序
  • 断线补发 — 客户端维护本地最大 Sequence,重连后拉取缺失消息
03

系统架构

网关统一入口,Java 业务层与 Python AI 层并行,通过消息队列异步协作。

AI / Agent 相关组件 加密 / 安全相关组件 通用业务与基础设施

核心设计决策

Java / Python 分离

Java 负责业务逻辑、并发控制、数据持久化与加密网关;Python 负责 LLM 调用、Agent 编排与文本处理。简单查询走 gRPC 同步调用,复杂 AI 任务走 RabbitMQ 异步队列。

异步 Agent 任务流

LLM 推理耗时 1–5 秒,不能阻塞 Tomcat / Netty 线程。

收到指令→ 入队列→ Celery 消费→ WS 推送

端到端加密方案

Signal Protocol 简化版,服务端零知识。

X3DHAES-256-GCM前向安全
04

功能模块详解

用户与推文系统

用户系统

注册登录、JWT、用户画像、隐私设置

推文系统

发布（含 @Agent 指令）、删除、查询、点赞转发

时间线

拉模式起步,进阶为推模式 + 缓存

通知系统

互动通知、Agent 任务完成通知

私信系统（重构重点）

单聊

  • 端到端加密消息收发
  • 已读 / 未读状态
  • 基于消息 ID 的逻辑撤回
  • LLM 辅助回复（客户端调用,可选开启）

群聊

  • 创建 / 邀请 / 退出 / 解散
  • 管理员与成员权限管理
  • Sequence Number 保证全局顺序
  • Sender Key 机制加密,支持 50–500 人

消息格式与密钥存储:

{ ciphertext, nonce, sender_id, timestamp, sequence }

密钥交换基于 X3DH 初始握手;私钥存于客户端本地（IndexedDB / Keychain）,服务端零接触。

Agent 系统（核心差异化）

Agent 生命周期是一条清晰的链路:

注册（配置化）→ 发现（运行时加载）→ 调用（@Agent 指令）→ 执行（LLM 推理）→ 返回（WS 推送）

LangGraph 编排（伪代码）:

from langgraph.graph import StateGraph

workflow = StateGraph(AgentState)

# 定义节点
workflow.add_node("parse_intent", parse_user_intent)
workflow.add_node("summary_agent", SummaryAgent.run)
workflow.add_node("rewrite_agent", RewriteAgent.run)
workflow.add_node("reply_agent", ReplyAgent.run)

# 按意图路由到不同 Agent
workflow.add_conditional_edges(
    "parse_intent", route_to_agent,
    {"summary": "summary_agent", "rewrite": "rewrite_agent", "reply": "reply_agent"}
)

app = workflow.compile()
  • RAG 增强 — 知识库为用户历史发布的推文
  • Embedding — sentence-transformers 生成向量
  • 检索 — ChromaDB 向量相似度搜索,注入 Prompt 提升相关性
